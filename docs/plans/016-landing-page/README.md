# 016: LP（トップページ）

`/` の仮の LP（002 で置いた「タイトル + ログインボタン」）を本実装に置き換える。

デザイン案は Artifact「assift LP 案A 作業台」（https://claude.ai/artifact/83KYVC3DY8QABJ3UoJK6rM ）。
3 案の比較 → 方向性の議論（参考: STORES）→ 案A のブラッシュアップ → 文言の見直しを経て、v21 以降を見た目と文言の正とする。
**Artifact と本プランが食い違うときは本プランを優先する**（Artifact は単一の HTML なので、色の値や部品の作りはアプリの規約に合わせて置き換える。§4）。

> 番号: 001 §6 では LP などの静的ページを 011 としていたが、011 はシフト表のリデザインに使われた。
> 本プランを 016 とし、データ移行・カットオーバーはその後ろに繰り下げる。
> AGENTS.md の「本番は 016 で設定する」は番号を外して「カットオーバーで設定する」に直す。

**状態: 実装済み（確認待ち。2026-10-06）。実装ログは §6。**

## 1. 目的と完了条件

### 目的

- 初めて来た店長が、**最初の画面で「何ができて、自分の手間がどう減るか」を掴み**、そのまま無料登録に進める
- 説明より先に**本物のシフト表に触れてもらう**（デモデータ。保存しない）。アプリと同じ部品で描くので、見た目が実物とずれない
- 情報は必要なだけ。白黒を基本にし、色はシフト表のマス（パターン色）からだけ持ってくる

### 完了条件

- 未ログインで `/` を開くと LP が出る。ログイン済みなら `/tenants` へ redirect する（005 §申し送り）
- ヒーロー: 見出し「シフト表づくりに、／もう時間はかけない。」は**どの画面幅でも 2 行**。サブコピー・CTA・マイクロコピー
- 触れるデモ: 来週（月〜日）× 7 人の表。マスを押すとアプリと同じポップオーバー（下書き / 確定・パターン）、長押しで下書き⇔確定、
  「AIで作成」で不足の枠が順に埋まり結果が出る、「元に戻す」「すべて確定」「共有」。フッターに配置 / 必要人数（不足は赤）
- できること（4 枚）・スタッフの画面・はじめ方（3 ステップ）・料金（計算スライダー）・よくある質問（5 問）・最後の CTA・フッター
- 見出しは文節の途中で折り返さない（§4.4）。和文と英数字の間に空白を入れない
- 360 / 390 / 768 / 1024 / 1280px で横にはみ出さない
- ルートの 404 の導線を `/` に変える（009 §7.1 の申し送り）
- `npm run format:check` / `lint` / `typecheck` / `test` / `build` が通る

### 3.1 なぜ `(public)/(site)/` か

009 §7.1 の申し送りどおり。公開シフト表（`/share/[code]`）は AppShell 無しの全画面テーブルで、LP のヘッダ / フッタが付くと
縦の高さ計算（`.page` の 100dvh）が崩れる。LP 側を入れ子のグループに寄せ、後で足す静的ページ（規約・プライバシーなど）も同じ layout に入れる。

### 3.2 ログイン済みの redirect

`page.tsx` で `getAuthUser()` → `redirect('/tenants')`。proxy には足さない（proxy は 3 段の合成にとどめる。AGENTS.md）。
cookie を読むので `/` は動的になる。デモの「来週」も描画時に決まるので、静的にする利点は無い。

### 3.3 デモはアプリの部品で描く

- 表は `ShiftTable.module.css` の `.table` / `.dateHead` / `.cell` / `.footRow`、セルは `ShiftCell`、ポップオーバーは `PatternPopover`、
  見出しは `DateHeaderCell` / `dateToneClass`、凡例は `PatternDescriptionList`
- 状態は `ShiftMap` / `applyAssign`（アサインの規則）/ `assignedCounts` + `coverageAt`（充足）。AI で入ったマスは `marked`（左上の点。012 §3.8）
- 列幅だけ LP 用に広げる（コンテナクエリで 7 列を枠いっぱいに。最小はアプリと同じ 56px）
- **AI はデモ用の貪欲法**（実物はソルバー。012）。守る条件: 出られない曜日・週の上限・遅番の翌日に早番を入れない・5 連勤しない。
  結果は「19 / 20枠を下書きで配置しました。」「◯/◯（◯）遅番1枠は、条件に合うスタッフがいません」
- 日付は**来週の月〜日**（JST）。祝日はサーバーで `holidaysIn()` して渡す（クライアントに祝日データを送らない。AGENTS.md）

`ShiftCell` / `PatternPopover` / `holdToToggle` は今 `shifts/_components`・`_lib`（ルート専用）にある。LP からルート専用の部品を import しないため、
`src/components/shiftTable/` へ移す（中身は変えない。`CalendarTable` の import だけ直す）。

## 4. 実装の規約との対応

### 4.1 色

Artifact の hex は Mantine の変数に置き換える（theme.ts に集約する方針）。

| Artifact | アプリ |
| --- | --- |
| 墨 #121214 / ボタン | `var(--mantine-color-dark-9)` 相当。ボタンは `color="dark"`（theme の既定） |
| 薄いグレーの面 #f3f3f4 | `var(--mantine-color-gray-1)` |
| 本文の灰 #5d5f66 | `var(--mantine-color-dimmed)` |
| ロゴのグレー #d4d5d9 | `var(--mantine-color-gray-4)` |
| 不足の赤 / 充足の緑 | `red-9` / `green-9`（シフト表のフッターと同じ） |
| パターン色 | `PATTERN_COLORS` から引き、`cellStyle()` で塗る |

### 4.2 書体

`next/font/google` の `Zen_Kaku_Gothic_New`（weight 400 / 500 / 700 / 900、`subsets: ['latin']`、`variable: '--font-site'`）を
`(site)/layout.tsx` だけで読む。アプリの他の画面は今のシステムフォントのまま。デモの表はアプリと同じシステムフォントで描く（実物と同じ見た目）。

### 4.3 Mantine と CSS Modules

レイアウト・ボタン・Accordion（FAQ）・Slider（料金）は Mantine。スタンプの傾き・トレー・カードの角丸・スマホの枠・
2 行固定の見出し・文節の折り返しは Mantine に無いので `Site.module.css` に書く。Server の page では Mantine のドット記法を使わない。

### 4.4 見出しの折り返し

`word-break: auto-phrase` は Chrome だけなので使わない。見出しは文節ごとに `display: inline-block` の span に分け、
切れ目でだけ折り返す。ヒーローは 2 行を `display: block; white-space: nowrap` にし、文字の大きさを画面幅から決める
（長い方の行が 10 文字）。

## 7. デモの入口（「さわって試せます」の置き換え）

### 7.1 問題

トレーの左上の「さわって試せます」は黒い塗りの角丸ラベル（`trayTag`）で、すぐ下の「AIで作成」（`color="dark"` の Button）と
色・太さ・角丸が同じだった。ラベルまで押せるように見え、押しても何も起きないので最初の一手でつまずく。

### 7.2 決めたこと

5 案（見出しにする / 表に薄い幕 / 光るボタン + 吹き出し / 指の実演 / チェックリスト）を触れるモックで比べ、
**見出しにする（A）+ 光るボタンと吹き出し（C）** にした。

- **A: 塗りをやめて見出しと説明文にする。** 「さわれるデモ」（kicker + 指のアイコン）/「来週のシフト表を、ここで作ってみてください」/
  「マスを押すと勤務を入れられます。「AIで作成」で空いた枠を埋められます。」。押せそうに見える物を本物のボタンだけにする
- **C: 最初の 2 手を指す。** 1 手目は「AIで作成」に波紋 +「まずはここを押してみてください」（§8 で吹き出しから状況の行の文へ移した）。押すと、AI が入れたマスのうち
  いちばん左（早い日付）のものへ移り「マスを押すと直せます」。ユーザーが自分で何か触ったら（マス・元に戻す・すべて確定・共有）消す
- **表に幕をかける案（B）は採らない。** LP の最初の画面の主役は色付きのシフト表で、スマホではそれがほぼ全面。幕で沈めると触る前の人に届かない
- 波紋の色は chrome と同じ墨（`dark-9` の透過）。LP は「色を持つのはマスだけ」（§2）なので新しい色を足さない
- 吹き出しは白地 + しっぽ（`Popover` の矢印）で、黒いボタンと形を変える。押せる物ではないので
  `withRoles={false}`（dialog の役割を付けない）・フォーカスを奪わない・`pointer-events: none`（下のマスを押せる）
- 吹き出しの `zIndex` はサイトのヘッダー（10）より下。スクロールでヘッダーの上に出ない
- 指す先が横スクロールで隠れたら吹き出しも隠す（`hideDetached`）。いちばん左のマスを選ぶのは、狭い画面で見えている側を指すため
- `prefers-reduced-motion` では波紋を止め、薄い輪だけ残す

## 8. デモのレイアウトシフト（状況の行）

### 8.1 問題

デモで操作すると表の位置が動いていた。原因は 2 つ。

1. **結果の帯が表の上に差し込まれる。** 「割り当てを考えています…」（1 行）→「19 / 20枠を…」（2〜3 行）。表が 100px 前後下がり、帯の高さも途中で変わる
2. **「元に戻す」が増えてボタンが折り返す。** 3 つなら 1 行に収まるが、4 つになるとスマホでは「共有」が 2 行目に落ちる

### 8.2 決めたこと

3 案（高さ固定の行 / 下端に重なるバー / 表の下に帯 + ボタンの入れ替え）をずれを実測するモックで比べ、**高さ固定の「状況の行」** にした。

- ツールバーと表のあいだに、2 行ぶんの高さで固定した行を**最初から**置く。中身だけを入れ替える
- 触る前は「◯枠が足りません」（勤務パターンごとの不足の合計。AI の「◯ / ◯枠」と同じ数え方）。
  1 手目の案内中は 2 行目を「まずは「AIで作成」を押してみてください」にする（§7 の吹き出しはこの行を隠すので、1 手目だけ行の文に移した）
- **「元に戻す」はツールバーのボタンではなく、この行の右端のリンク**。ツールバーは「AIで作成・すべて確定・共有」の 3 つで固定し、折り返さない。
  アプリでも元に戻すは AI の結果パネルの中にある
- 文は 1 行ずつに収める（スマホで 24 文字前後）。はみ出したら省略（…）で切り、高さは変えない。`title` に全文
- 埋まらなかった枠の文を短くした: 「10/18（日）遅番1枠は、条件に合うスタッフがいません」→「遅番1枠は、条件に合う人がいません（日）」。
  デモは 1 週間なので曜日で日が決まり、フッターの赤と対応する。勤務が混ざるときは「2枠は、…（土・日）」
- 不足の数はマスを押すたびに変わるので、触る前の文は読み上げない（`aria-live="off"`）。操作の結果だけ `polite`
- 下端に重なるバー（アプリのスマホと同じ形）は、出ている間「配置 / 必要人数」の行が隠れるので採らない。AI の効果が一番見えるのが赤 → 緑のこの行

## 12. サブコピーを短くする

「スタッフの都合や勤務の上限を守って、AIが下書きを作ります。／あとは内容を確認して、URLで送るだけ。」→
「お店とスタッフの希望をAIがシフト表に。／スタッフにはURLを送るだけ。」

- 「スタッフの都合」だけだと、スタッフが調整の妨げのように読める。実際は店の条件（必要人数）とスタッフの希望の両方を満たす作業なので、両方を並べ、「都合」より前向きな「希望」にした
- 「下書き」「確認して」を外した。AI が作ったものを確認するのは当たり前で、書くと「そのままでは使えない」に読める
- 2 行目は「スタッフには」の「は」で、店長は AI で作る／スタッフは URL を受け取るだけ（アプリも登録も要らない）の対比にした。送り先も明示される
- 「、」を外した。15〜20 字の 2 行は改行が区切りになり、各行を「、」で割ると同じ形が並んで作り物っぽく見える。どちらの行も「、」なしで誤読しない
- 行数: 1280px / 768px / 375px / 360px で 2 行（以前は 375px で 3 行）。320px では 3 行

## 13. デモの「共有」をカードにする

「共有」を押した結果が状況の行（表の上の 2 行）にしか出ず、ボタンから離れていて文字も小さいので気付きにくかった。
実物の共有モーダル（`ShareModal`）の発行後の形をなぞったカードを、デモの枠の上に出す（`DemoShareCard`）。

- **画面全体ではなく、デモの枠の上にだけ重ねる**（`.demo` を `position: relative` にし、`.shareLayer` を `inset: 0`）。
  Mantine の `Modal` は画面を暗くしてスクロールも止めるので、LP では本当に何かを発行したように見えて身構える
- **枠の上端に寄せる。** 中央だとスマホ（表が縦に長い）では押した「共有」から離れ、画面の外に出ることがあった
- **コピーは見た目だけ**（押せない・読み上げない）。ダミーの URL は開くと 404 で、コピーできても押した人をがっかりさせるだけ。
  代わりに主ボタン「スタッフの画面を見る」で、すぐ下の `StaffView`（スタッフが開くページの例）へスクロールする。
  「URL を発行 → スタッフにはこう見える」がそのままつながる
- URL は `assift.com/share/a8Kx3mQp`（実物と同じ 8 文字・同じ字の集合から選んだ固定値）
- 閉じるのは ×・枠の外・Esc。開くと主ボタンにフォーカス、閉じると「共有」に戻す。「最初からやり直す」でも閉じる
- 状況の行の文（「共有のURLを発行しました（デモ）。」）も残す。カードを閉じたあとに何をしたかが残り、読み上げもこちらが担う
- `StaffView` に `id="staff-view"` と `scrollMarginTop: var(--site-anchor-offset)`（sticky のヘッダーに隠れない）。
  id は `_lib/sectionIds.ts` に置く（Server の節と Client のデモの両方が引く。`'use client'` のファイルから定数を import すると、Server 側にはクライアント参照が届く）
- 重なり: 吹き出し（5）より上、サイトのヘッダー（10）より下の 6
