## 2. 文章の方針

## 3. 個人情報保護法で必要なもの

| 条文 | 内容 | 項 |
| --- | --- | --- |
| 21 条 | 利用目的の公表 | 3. 使う目的 |
| 27 条 | 第三者提供の制限と例外（委託・事業承継・法令） | 5. ほかの人や会社に渡す場合 |
| 28 条 | 外国にある第三者への提供（委託も含む）。基準適合体制 + 相当措置、求めに応じた情報提供。国の制度は個人情報保護委員会の調査へリンク | 6. 預け先と外国での扱い |
| 32 条 | 保有個人データに関する事項の公表（名称・住所・代表者、利用目的、開示等の手続き、安全管理措置、苦情の窓口） | 8・10・12 |
| 26 条 | 漏えい時の委員会への報告と本人への通知 | 8. 情報を守るための取り組み |

住所と代表者名は「求めがあれば遅滞なく回答」とした（32 条の「本人の知り得る状態」には、求めに応じて遅滞なく回答する場合を含む）。

## 4. assift に固有の論点（実装との突き合わせ）

| 論点 | 実装 | 書き方 |
| --- | --- | --- |
| スタッフの情報 | 店長が入れる（`staffs.name`、勤務条件、制約・AI 指示のメモ） | 店舗から預かって扱う（委託）。スタッフ本人の求めはまず店舗へ。私たちは店舗と相談して対応 |
| 共有リンクの閲覧者 | ログイン不要。アクセスログのみ | 対象者に含め、アクセスの記録が残ることを書く |
| AI | Vercel AI Gateway 経由で OpenAI（規約では Anthropic / Google も併記）。学習に使わない。提供元は不正利用の監視で一定期間保持（OpenAI は 30 日） | 預け先に列挙。保存期間の項で「提供元が定める期間」 |
| Cookie | Supabase の認証 cookie、`assift-current-tenant`、パスワード再設定の短命 cookie。localStorage にコピー条件・初回の案内。アクセス解析（未実装） | 必要なものだけ。アクセス解析は Cookie を使わない Vercel Web Analytics。広告は使っていない |
| 安全管理 | TLS、RLS によるテナント分離、パスワードのハッシュ、service_role の限定 | 8. に箇条書き |
| 決済 | `profiles.stripe_*` | カード番号は Stripe が受け取り、保存しない |
| 退会 | cascade で即削除 | バックアップに一定期間残る（規約第 11 条と同じ） |

## 5. やらないこと

- 版の管理と改定の予告（016 §5.1 と同じく、最初の改定のときに作る）
- Cookie の同意バナー（必要な Cookie だけで、アクセス解析も Cookie を使わない）
- アクセス解析の導入（`@vercel/analytics` と `<Analytics />`）。**ポリシーは導入済みとして書いているので、公開（カットオーバー）までに入れる**

### 2026-10-07（v1 との比較）

v1 のポリシー（全 10 条。よくあるひな形）と比べた。

v1 から取り入れたもの:

- 3. 使う目的: 「利用規約に違反したユーザーの特定・利用のお断り」を明記（v1 第 3 条）
- 5. ほかの人や会社に渡す場合: 例外に「国や自治体の仕事への協力」「公衆衛生・子どもの健全な育成」（v1 第 5 条。法 27 条 1 項の 4 号と 3 号）
- 10. 確認・訂正・削除: 結果を知らせること、応じない場合があり理由を添えて知らせること（v1 第 6〜8 条。法 33 条ほか）

v1 から外したもの:

| v1 | 外した理由 |
| --- | --- |
| 第 1 条 個人情報の定義 | 法律の定義を写しただけ。読み手に要らない |
| 第 2 条 氏名・生年月日・住所・口座・カード番号・免許証番号を尋ねることがある | v2 は集めていない。実際に集めるものだけを書く |
| 第 2 条 提携先（広告主など）から集める | していない |
| 第 3 条「上記の利用目的に付随する目的」 | 範囲が曖昧（利用目的は「できる限り特定」が必要。法 17 条） |
| 第 5 条 オプトアウトによる第三者提供（委員会への届出） | していない。予定もない |
| 第 5 条 共同利用 | していない |
| 第 6 条 開示の手数料 1 件 1,000 円 | 無料にした（ほとんど画面でできる） |
| 第 6 条 履歴情報・特性情報は開示しない | 法の開示対象を狭める読み方になる。応じない場合は法の例外で足りる |
| 第 9 条 通知なしで変更できる | v2 の規約と同じく、変更はページで知らせ、大事な変更はメールでも知らせる |

v1 にあって v2 では未決定のもの:

- 新機能・キャンペーン・他サービスの案内メール（v1 第 3 条）。送るなら利用目的に入れる（配信停止の仕組みも要る）
- 窓口のメールアドレス: v1 は `info@assift.com`、v2（規約）は `support@assift.com`

### 2026-10-07（支払いの情報・案内メール）

- 2. 集める情報: 支払いの情報を具体的にした。カード番号は Stripe の画面（Checkout / Elements）に直接入るので**私たちには届かない**が、
  Stripe から請求先の名前・メールアドレス、カードの種類・下 4 桁・有効期限を受け取れる（API で読める）。振込は振込人の名前が分かる。
  v1 の「口座番号・カード番号を尋ねる」とは違い、尋ねるのではなく Stripe 経由で受け取るものだけを書いた
- 3. 使う目的: 案内メール（新機能・キャンペーン・ほかのサービス）を追加。「いつでも止められます」と書いたので、**案内メールを初めて送るまでに**:
  - 受け取りを止める仕組み（設定画面の切り替え + メールのワンクリック解除。Gmail / Yahoo の一括送信者の要件）
  - 特定電子メール法の表示（送信者名・解除の方法・連絡先）。登録ユーザーは取引関係にあるので事前の同意は要らないが、止める手段は要る
  - V2 へのリニューアルのような、サービスそのもののお知らせは案内メールではない（止められなくてよい）
- 窓口: ポリシーのお問い合わせ先は `support@` のまま（受け付けの窓口は 1 つ）。案内メールの送信元は別に決める

### 2026-10-07（未確定の値を決定）

- DB は日本（東京）、メールは Resend、決済は Stripe、住所・代表者名は求めに応じて回答
- アクセス解析を入れる: 7. Cookie に目的・送る項目・止め方を足し、6. 預け先にも足した。ツールは `PRIVACY.analytics` に集めた（仮: Google Analytics）
