# 011 シフト表のリデザイン

シフト表（保護ルートと公開ページ）の見た目を作り直す。機能・データ・クエリは変えない。

## 1. 動機

v1 をそのまま写した表は、線と記号が情報より目立っていた。洗い出した問題は 4 群。

| 群   | 問題                                                                                                     |
| ---- | -------------------------------------------------------------------------------------------------------- |
| 罫線 | 全マスに同じ濃さの 1px 罫線。データ（色）より枠が目立ち、Excel の印象になる                              |
| 色   | 下書きが細い枠線しか色を持たず、離れて見るとパターンを読めない。確定はベタ塗りで強すぎる                 |
| 色   | 担当不可の `gray-1` が「空」と紛らわしく、グレーのパターン（明けなど）とも意味が衝突する                 |
| 記号 | `2/0` が読めない（必要人数 0 の日にも出るので指標として機能していない）。名前の横の `4` にラベルが無い   |
| 記号 | メモの鉛筆アイコンが内容ゼロで 14 個並び、ヘッダーの高さと視線を取る                                     |
| 密度 | ヘッダーに 曜日・日・充足数・充足バー・メモ の 5 つが等間隔で積まれ、どこから読むか決まっていない       |

## 2. 決めたこと

デザイン案はキャンバスで比較して決めた（案 A ソフトフィル / 案 B ソリッドブロック / 案 C カラーレール →
案 A を採用し、満杯時の検証とヘッダーの検証を経て確定）。

1. **下書き = パターン色の淡塗り + 同系の濃い文字 / 確定 = ベタ塗り + 太字。**
   塗りの濃さで区別するので、どちらも色がセル全面に出る
2. **パレットは DB を触らない。** 保存済みの hex から `tintColor()` / `inkColor()` を導出する。
   v1 から移行した行も、ユーザーが後から選んだ色も同じ規則になる
3. **罫線は 3 本だけ**（ヘッダー下 / 名前列の右 / フッター上）。本文には縦罫も横罫も引かない。
   週の区切り線も引かない（土日祝のヘッダーの色で位置が分かる）
4. **土日祝の色はヘッダーの面だけ。** 本文の列は塗らない。全員にシフトが入った状態で検証し、
   本文まで塗るとパターン色と競合することを確かめた
5. **今日はヘッダーセル上端の 3px の黒いバー。** 日付を囲むリングも列の塗りも使わない
6. **充足（配置 / 必要人数）は表の下のフッターへ。** 列の集計なので日付ヘッダーではなく合計行に置く。
   バーは廃止して数字だけ。0/0 の日は出さない。**必要人数モーダルもフッターからだけ開く**
7. **担当不可は 45° の斜線ハッチ**（ベタのグレーをやめる）
8. **記号を減らす。** メモは文字がある日だけ（空の日のペンはホバー時だけ）。`⋮` もホバー時だけ。
   勤務日数は `4日` と単位を付け、min-width で 1 桁と 2 桁の幅を揃える
9. セルの余白は上下左右とも 3px、角丸 3px。**隙間は padding だけで作る**
   （片方を border で作ると縦横で幅が揃わない）

### 3.1 インクの決め方

淡塗りは `パターン色 12% + 白 88%`。その上に載せる文字は、輝度が `0.13` に収まるまで
sRGB の各チャンネルを同じ比率で落とす（二分探索）。比率を決め打ちにしないのは 20 色の明るさが
ばらばらだからで、暗い色（紺・茶）はそのまま返るので色味が保たれる。

**`TINT_RATIO` と `INK_MAX_LUMINANCE` は対で調整する。** 片方だけ動かすと読めなくなる。
20 色すべてでコントラスト比 4.5:1 以上になることを Vitest で固定した。

### 3.2 やらなかったこと

- **PDF は v1 のまま**（白地 + 上辺の色帯）。紙は淡い塗りが飛びやすく、出力を目で確かめてから
  でないと動かせない。`lib/pdf/pdfCellStyle.ts` の冒頭に、web と規則が違うことと揃えるときの
  手順を書き残した
- `PATTERN_COLORS`（DB に入る 20 色）は変えていない。既存の行と新しい行で色が食い違うため

## 5. 実装ログ

- 充足をフッターに移したので、日付ヘッダーの `aria-label` から `2/6` を外し、フッターのセルに移した。
  **入口も分けた**: 必要人数はフッターだけ、日付メモはヘッダーだけ。同じ列に 2 つの動詞を重ねない
- 日付ヘッダーは **セル全体を 1 つのボタン**にした。曜日・日付・メモのどこを押しても日付メモが開く。
  中のメモ行（`DateNoteCell`）は押せない `<div>` になり、ペンはヘッダーのホバーで出る
- フッターの sticky は `<tfoot>` ではなく **セル（`th` / `td`）に当てる**。`tfoot` / `tr` への
  `position: sticky` はブラウザによって効かない
- 名前列のセルは sticky-left と sticky-bottom が重なる。`position: sticky` は 1 つでも
  複数方向のオフセットが効くので、`left: 0` と `bottom: 0` を同じ要素に書けばよい
- セルのホバーは `background-color` ではなく `filter: brightness()`。背景で上書きすると
  `cellStyle()` が inline で当てたパターン色が消える
- 今日のバーは **全列に置いて色だけ切り替える**。今日の列にだけ要素を足すと、その列だけ 3px 下がる

## 6. 追補: URL 共有モーダル（案 A「この期間の URL」）

`ShareModal.tsx` は v1 の移植のまま、発行ボタン → 注意書き → 共有中の一覧 → 期限切れの一覧を同じ強さで縦に積んでいた。
デザイン案を 3 つ比較して（A この期間の URL / B 共有の台帳 / C スタッフに届ける）、**案 A** を採る。

### 6.1 課題（抜粋）

| 課題 | 現状 |
| --- | --- |
| 発行した URL がどこに出たか分からない | ボタンは最上部、URL は注意書きの下の一覧の先頭。通知だけで行は強調されない |
| URL がいちばん目立たない | `Anchor` は primaryColor（gray）の 6 番で本文より薄い。コピーは 28px の subtle アイコンで、結果はツールチップだけ |
| いつまで見られるかが行ごとに分からない | 注意書きに「終了日の7日後に無効」という規則があるだけ。行には取得日時が出る |
| 注意書きの重みが揃っている | 「誰でも見られる」と「リアルタイムに反映」が同じ xs。**下書きも公開される**ことが書かれていない |
| 期限切れがまだ使えるように見える | 共有中と同じカード + リンク + コピー。押すと 404 |
| 期限切れの期間ではボタンが説明を兼ねる | disabled のボタンの中に「過去のシフト表は共有できません」 |
| 解除の確認に結果が書かれていない | 「シフト表の共有を解除しますか？」だけ。期間も、送った URL が開けなくなることも無い |

### 6.2 決めたこと

1. **見出しに期間名を入れる**（`2026年10月のシフト表を共有`）。`formatPeriodTitle()` をツールバーと共有する
2. **表示中の期間の共有を上に出す。** 期間が完全に一致する共有中の行のうち最新の 1 件を「この期間の URL」にし、
   発行ボタンがあった場所に読み取り専用の入力 + 文字付きの「コピー」ボタンで出す（押すと「コピー済み」）
3. **同じ期間の 2 本目は禁止しない**（v1 と同じ。サーバーも拒否しない）。ただし主導線からは外し、
   「この期間の URL」の `…` メニューに「別のURLを発行」として置く。古いほうは下の一覧に回る
4. **「作り直す」は入れない。** 漏れたときは「共有停止」→ 発行し直す
5. **期限は日付で出す。** `lib/shares/expiry.ts` に `shareLastDay()`（= 終了日 + `SHARE_GRACE_DAYS`）と
   `shareDaysLeft()` を足し、`isShareEnabled()` も `shareLastDay()` で書き直す。残り
   `SHARE_ENDING_SOON_DAYS`（3）日以下はオレンジ
6. **注意は 1 行**：「URLを知っている人は誰でも見られます。ログインは要りません。下書きのシフトも表示されます。」
   下書きの公開は続ける（公開ページは変えない）
7. **他の期間の共有中は 1 行ずつ**（カードをやめて区切り線だけ）。期間 / 期限のバッジ / コピー / `…`（開いて確認・共有停止）
8. **期限切れは折りたたむ。** 行は文字だけにして、リンクとコピーを外す
9. **期限切れの期間では発行ボタンを出さず、文で理由を書く**（`SHARE_EXPIRED_MESSAGE` + 公開期限の日付）
10. **用語は「共有停止」「URL」に揃える。** 確認は「◯◯の共有を停止します。送ったURLは開けなくなります。」

### 6.3 変えないもの

- Server Action（`createShare` / `deleteShare`）、`listShares()`、公開ページ、スキーマ

  コピー欄を発行ボタンと同じ場所に出すことで代わりにする

## 7. 追補: 共有モーダルの視線誘導（案 A-3「出し分け」）

§6 の構成は情報が揃ったが、同じ強さの要素が 4 つ並び、どこから読むかが決まっていなかった。
3 案（A URL がヒーロー / B スタンプ / C 伝票）を比べて A を採り、さらに A の派生 3 案
（A-1 URL を見出しに / A-2 状態カード / A-3 注意書きの出し分け）から **A-3** を採る。

### 7.1 課題

| 課題 | §6 の状態 |
| --- | --- |
| 期間の文字が全部同じ強さ | 主役の `2026/10/1 〜 10/31` も一覧の `2026/9/1 〜 9/30` も 16px 相当の太字で、年が毎行つく |
| 注意書きが操作と同じ重さ | 4 つのバッジ + 4 文がモーダルの 3 分の 1。発行前後を問わず常に末尾に出る |
| 面が並列 | 発行帯（gray-1）・ほかの共有中（gray-0）・行ホバー（gray-1）が近いトーンで、どれが上か読めない |
| 発行後の URL が細い | 14px/400 の入力欄。下の期間ラベルより軽い |

### 7.2 決めたこと

1. **期間はタイトルへ**（§6.2 の 1 をここで実装）。`2026年10月のシフト表を共有`。`formatPeriodTitle()` をツールバーと共有し、年だけ dimmed にする
2. **注意は押す前に読ませ、押したあとは縮める。** 発行前は幅いっぱいの発行ボタンの上に 3 行（誰でも見られる / 下書きも表示・変更も反映 / `11/6` まで公開）。
   発行後は URL の下に 1 行（`URLを知っている人は誰でも見られます · 下書きも表示`）。別の日に開き直した人のために「誰でも」は残す
3. **塗りボタンは常に 1 つ。** 発行前は発行、発行後はコピー
4. **URL は入力欄ではなく文字。** 15px、オリジンを gray-6・コードを本文色にする。溢れたら先頭側を省略する（コードは切らない）
5. **公開状態は URL の直下の 1 行**（緑の点 + `公開中 · 10/6 まで` + dimmed の `あと12日`）。残り 3 日以下は橙。右端に「開く」と `…`
6. **面の塗りをやめ、区切りは線だけ。** ほかの共有中と期限切れは上に 1 本の線を引いてまとめ、行の間は gray-1 の線
7. **一覧の期間は年を落とす。** タイトルと同じ年なら `9/1 〜 9/30`。確認ダイアログは単独で読まれるので年を残す

## 8. 追補: シフトコピーモーダル（案 A「期間で選ぶ」）

`CopyModal.tsx` は v1 の移植のまま、注意（電球の Alert）→ 日付欄 5 つ → 勤務パターンのチェックボックス → ボタンを縦に積んでいた。

### 8.1 課題

| # | 課題 | 現状 |
| --- | --- | --- |
| 1 | 規則が「ヒント」の見た目 | 灰色の Alert に「上書きされません」だけ。**確定が下書きに戻る**・**退職者の行は写らない**はどこにも無い |
| 2 | 期間ではなく日付 4 つを選ばせる | 使う場面の大半は「前の期間 → 今の期間」で既定値もそうなのに、期間名（`2026年9月`）が出ない。(From)/(To) の和英併記 |
| 3 | 曜日が見えない | 9/1(火) → 10/1(木) と曜日がずれることが分からない |
| 4 | 日付欄が 5 つ縦に並ぶ | 開始日 / 終了日が 2 回ずつ + 読み取り専用。1 つ変えるたびにカレンダーのモーダルが重なる |
| 5 | 「※最大31日間」が常駐 | 超えたときは終了日の下にもエラーが出るので二重 |
| 6 | **前回条件が日付ごと復元される** | 以前「5月 → 6月」とコピーしていると、10 月を見ながら開いてもコピー先が 6/1。気付かず押すと見ていない期間へ写り、成功後に 6 月へ移動する |
| 7 | 計算値が入力欄に見える | 読み取り専用の filled 入力。空く最終日・次の期間へのはみ出しは押したあとの通知でしか分からない |
| 8 | 勤務パターンに色が無い | 名前だけの縦リスト。勤務と休みが混ざる |
| 9 | 押す前に結果が分からない | ボタンがタイトルの繰り返しで行き先が無い。キャンセルが無い |

### 8.2 決めたこと

1. **既定は「期間で選ぶ」。** コピー元 / コピー先を 1 行ずつの枠に並べ、`‹ ›` で期間ごと動かす（`prevStart` / `nextStart`）。
   期間名は `formatPeriodTitle()`（ツールバーと同じ）、下に `9/1（火） 〜 9/30（水）`（土は blue-8、日は red-8）。
   週・2 週間など期間名がそのまま範囲のときは、下の行を曜日だけにする
2. **任意の日付は「日付を指定」の中へ。** コピー元は `DatePickerInput type="range"` 1 欄、コピー先は開始日 1 欄 + 計算した終了日の文字。
   `dropdownType="modal"` は続ける（008 §10.4）。31 日の注意は常駐させず、超えたときのエラーだけにする
3. **コピー先は常に表示中の期間から始める。** 前回条件から戻すのは勤務パターンの選択だけ（課題 6）。
   前回のコピー元が「前回のコピー先の 1 つ前の期間」でなかった（= 既定をわざわざ変えた）ときだけ、
   `前回のコピー元：6/1 〜 6/7` + 「これを使う」を 1 行出す。押したときだけ入る（テンプレートの週を使い回す店舗向け）。
   保存形（`copyConditionsSchema`）と保存のタイミング（送信成功時）は変えない
4. **押す前に結果を見せる。** 曜日のずれ（`曜日がずれます（9/1 火 → 10/1 木）` / `曜日もそろいます`）。
   コピー元とコピー先が同じ開始日なら理由を出して送らせない（全セルが自分自身と衝突して 0 件になるだけ）
5. **ボタンは `シフトをコピー`。** 左に「キャンセル」
6. **規則は押す前の 1 行**（共有モーダルの注意と同じ組み）: コピー先に入っているマスは残る
7. **勤務パターンは表の凡例と同じ札で選ぶ。** 選択中は `chipStyle()`（淡塗り + ink）+ チェック、外したものは白地 + 色の四角 + dimmed。
   勤務と休みを分けて並べ、見出しに `6/7` の件数と「すべて選ぶ / すべて外す」。パターンが 0 件なら理由と設定へのリンク

ツールメニューの項目。

### 8.6 実装ログ

- 表示の判断（期間かどうか、期間名、前後の期間、空く日 / はみ出す日、曜日のずれ、前回のコピー元の提案、ボタンの文言）は
  `_lib/copyPlan.ts` の純関数にし、Vitest で固定した。期間名は `formatPeriodTitle()`、前後は `prevStart` / `nextStart` をそのまま使う
- 範囲ピッカーは 1 回目のクリックで `[開始, null]` を返すので、コピー元は `DatesRangeValue` のまま state に持つ。
  途中の状態では送信できない（`fromTerm` が null）。`allowSingleDateInRange` で 1 日だけのコピー元も選べる（従来どおり）
- 「日付を指定」から「期間で選ぶ」に戻すときは、コピー元 / コピー先それぞれの開始日を含む期間へそろえる
- 空く日 / はみ出す日の注記は期間で選んでいるときだけ出す。日付指定で 7 日を月の途中へ写すと「残り 24 日が空のまま」になり、
  意図どおりのものまで注記になるため。はみ出したときの成功通知（「一部は次の期間にあります」）は従来どおり
- 注記は最初「10/31（土）はコピー元が無いので空のままです」としたが、440px のモーダルで 1 文字だけ折り返したので `は空のままです` に詰めた
  （30 日と 31 日が上下に並んでいるので理由は読める）
- 未選択の案内（「写す勤務パターンを選んでください」）は最初フッターの左に置いたが、キャンセルと行き先入りのボタンを押し出して折り返したので、札の下へ移した
- 白いパターンの札は `chipStyle()` が文字色を当てないので、選択中は CSS で本文色に戻す（外したものの gray-6 のままだと選択が読めない）
- 文字ボタン（日付を指定 / すべて外す）は Mantine の subtle gray の既定（本文色・600）だと期間名より強く見えたので、500・gray-7 に下げた
- 前回条件の保存形は変えていない（`fromStart` / `fromEnd` / `toStart` / `patternIds`）。`toStart` は「前回のコピー元が既定どおりだったか」の判定にだけ使う
- 送信の確認で、ローカル DB の 10 月に 9 月のシフトが下書きで入っている（seed を戻すなら `npx supabase db reset`）
- 期間名の横の `表示中` タグは外した。開いた時点のコピー先は必ず表示中の期間なので、既定の繰り返しにしかなっていなかった
- 勤務パターンの見出しは `写す勤務パターン` から `コピーする勤務パターン` にした。未選択の案内も同じ言い方に揃えた
- 注意は「コピー先にシフトが入っているマスはそのまま残ります」「退職したスタッフの行はコピーされません」にした。ボタンの行き先（`2026年10月へコピー`）は外し、`シフトをコピー` に固定した。`copyButtonLabel` は削除した
- 「退職したスタッフの行はコピーされません」は外した。退職者はシフト表に出ないので、コピー対象に入っていると誤認しない
- 「下書きで入ります。確定は引き継ぎません」も外した。コピー結果は淡い塗りの下書きとして表に出るので、押す前に読ませなくても分かる
- 期間の日付は `8/1 土` から `8/1（土）` にした。空く日の注記（`10/31（土）`）と揃える。曜日だけの行と `曜日がずれます（9/1 火 → 10/1 木）` は括弧を重ねない
- 期間の行から `· 31日` を外した。期間名と日付で長さは分かり、空く日・はみ出す日は注記が説明する。日付指定の入力欄の日数は、31日を超えたかがそこで分かるので残した
- 「12/31（木）は空のままです」は外した。コピー先の日付がそこで終わっているので、空く日は範囲を見れば分かる。はみ出す日（次の期間の表に入る）は残した
- 「12/1（火）は2026年12月の表に入ります」も外した。コピー先の日付がすでにその日で終わっている。はみ出したときの通知（「一部は次の期間にあります」）は残した
- 成功通知の「（一部は次の期間にあります）」も外した。はみ出しはコピー先の終了日で分かり、通知は「シフトをコピーしました」に揃えた。移動の条件（開始日が表示期間の外のときだけ）は変えていない
- 勤務パターンの札は、チェック（14px）が色の四角（10px）と入れ替わると幅が 4px 広がって隣がずれた。印を 14px の枠に収めて、選択しても幅が変わらないようにした
